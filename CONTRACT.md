# Контракт пакетных экспериментов

Этот документ задаёт целевой интерфейс запусков и формат результатов. Поля показателей, которые ещё не реализованы, сохраняются в схеме как заглушки со значением `null` (пустая ячейка в CSV); их отсутствие не должно менять состав столбцов. Любое изменение контракта требует согласованного обновления кода, тестов и этого документа.

## Единичный прогон

```text
run_once(plan, seed, T, W, demand_scale, options) -> dict
```

- `plan` — идентификатор или описание параметров плана светофора, включая схему фаз.
- `seed` — целое значение из реестра ниже.
- `T` — горизонт прогона в модельных секундах; `W` — прогрев, `0 <= W < T`. Показатели интервала наблюдения вычисляются на `[W, T]`.
- `demand_scale` — множитель интенсивности спроса.
- `options` — дополнительные настройки, в том числе контроллер, пиковый въезд и параметры физики. Неуказанные настройки берутся из явно зафиксированных значений по умолчанию.
- Возвращаемый словарь содержит метаданные прогона и все поля показателей из раздела «Показатели». Неизмеряемые или пока не реализованные показатели возвращаются как `None`.

Один вызов — один прогон одного плана с одним SEED. При парном сравнении планы запускаются на одних и тех же потоках (общий SEED и воспроизводимые независимые потоки случайности).

### Воспроизводимые потоки случайных чисел

Для общего `SEED` используются семь независимых генераторов `random.Random` с дочерними seed `seed_k = SEED * 1000 + k` (без `hash()`):

| `k` | Назначение |
| --- | --- |
| 0–3 | Интервалы прибытия на подходах N, E, S, W соответственно |
| 4 | Манёвр |
| 5 | Выбор полосы |
| 6 | Траектория |

Манёвр, случайные приоритеты полос и выбор траектории машины фиксируются при её появлении. При одинаковых параметрах спроса план светофора не сдвигает последовательность обращений к генераторам и не меняет моменты прибытия. Интервалы прибытия делятся на `rate_multiplier(approach, t)`; в `scenario.py` для варианта команды 2 множитель равен `0.95`.

## Файлы CSV

Все файлы записываются в `results/`. Имена файлов содержат уникальный суффикс серии, например дату-время или идентификатор запуска:

- `results/runs_*.csv` — подробные результаты, **одна строка на один прогон**.
- `results/timeseries_*.csv` — по запросу (`--timeseries`): очередь каждую модельную секунду, одна строка на прогон и момент `t = 1..T`. Столбцы: `run_id, plan_id, seed, t, queue, queue_N, queue_E, queue_S, queue_W`; `queue` — сумма по въездам. Ряд включает прогрев, фильтрация по `W` — на стороне анализа.
- `results/demand_log_*.csv` — журнал входного спроса (`vehice_id, t_born, entry_side, turn`), блок `Launch i` на каждый SEED серии; журнал не зависит от плана, поэтому пишется один раз на SEED.
- `results/summary_*.csv` — сводка по серии прогонов. Одна строка соответствует одной агрегируемой группе (как минимум плану и режиму эксперимента); состав группы задаётся полями группировки, а не неявно порядком строк.

`runs_*`, `summary_*` и `timeseries_*` имеют заголовок, UTF-8-кодировку и стабильный порядок столбцов. Числа записываются числовыми значениями, отсутствующие значения — пустыми ячейками. Параметры, определяющие прогон, не должны теряться при агрегировании: в подробном файле они записываются в каждой строке, в сводке — в полях группировки либо как явно указанные диапазон/набор значений.

### Поля `runs_*.csv`

Обязательные поля идентификации и настройки (имена столбцов):

```text
run_id, plan_id, seed, T, W, demand_scale, phase_scheme, controller,
peak_enabled, peak_approach, peak_start, peak_end, peak_multiplier, physics
```

`run_id` уникален в пределах серии; если настройка неприменима, поле остаётся пустым. Поля параметров светофорного плана (например, `cycle`, `ns_green`, `ew_green`, `clearance`) добавляются в этот блок при использовании; для одного поля сохраняется одно и то же имя во всех файлах.

После метаданных следуют все показатели из раздела «Показатели» в указанном там порядке. Повторные и пропущенные столбцы не допускаются.

### Поля `summary_*.csv`

Сначала записываются ключи группировки:

```text
plan_id, phase_scheme, controller, physics, demand_scale, T, W, n
```

Затем для каждого агрегируемого числового показателя `M` — поля:

```text
M_mean, M_std, M_ci95_low, M_ci95_high
```

Также фиксируются `paired_with_plan_id`, `paired_n`, `paired_difference_mean`, `paired_difference_std`, `paired_difference_ci95_low`, `paired_difference_ci95_high`, `objective_name`, `objective_value` и `notes`. Если поле ещё не применимо или расчёт не реализован, оно остаётся пустым; ноль не используется как заглушка. Парная разность приводится относительно `paired_with_plan_id` и считается только по сопоставленным прогонам.

Доверительный интервал — `x̄ ± t·s/√n` (Стьюдент, `s` с делителем `n − 1`, двусторонний 95%); при `n = 1` `M_std` и границы пусты. Агрегируются все числовые показатели из раздела «Показатели» (кроме `objective_value` и `conflicts_by_phase`); если показатель не реализован хотя бы в одном прогоне группы, его четыре поля пусты. Поле `notes` содержит набор SEED и параметры плана группы: `seeds=201-210; cycle=42; ns_green=18; ew_green=18; clearance=3`.

## Показатели

Ниже приведён полный целевой список имён полей для результатов прогона. Это стабильные snake_case-имена столбцов. Если показатель не реализован, не применим или не вычислим для данного прогона, его значение — `null`/пустая ячейка.

| Поле | Смысл |
| --- | --- |
| `generated` | Всего сгенерировано автомобилей |
| `completed` | Автомобили, завершившие поездку |
| `remaining` | Незавершённые автомобили (`generated - completed`) |
| `mean_queue_after_warmup` | Средняя суммарная очередь на `[W, T]` |
| `max_queue_after_warmup` | Максимальная суммарная очередь на `[W, T]` |
| `final_queue` | Очередь в конце прогона |
| `delay_completed_sec` | Средняя задержка завершивших поездку; сохраняется для сопоставимости с исходной моделью |
| `flow_completed_per_hour` | Поток завершивших поездку, в автомобилях в час |
| `conflicts` | Число модельных конфликтов на интервале наблюдения |
| `conflicts_per_100_completed` | Конфликты на 100 завершивших поездку |
| `accumulated_delay_machine_sec` | Накопленная задержка всех автомобилей, включая незавершённые, в машино-секундах |
| `mean_queue_N`, `mean_queue_E`, `mean_queue_S`, `mean_queue_W` | Средняя очередь по каждому въезду на `[W, T]` |
| `max_queue_N`, `max_queue_E`, `max_queue_S`, `max_queue_W` | Максимальная очередь по каждому въезду на `[W, T]` |
| `mean_delay_N_sec`, `mean_delay_E_sec`, `mean_delay_S_sec`, `mean_delay_W_sec` | Средняя задержка по въезду |
| `delay_p95_sec` | 95-й процентиль задержки; правило отбора автомобилей фиксируется в `options`/`notes` и отчёте |
| `queue_mean_last_quarter` | Средняя суммарная очередь в последней четверти прогона |
| `queue_mean_second_quarter` | Средняя суммарная очередь во второй четверти прогона |
| `objective_value` | Значение заранее объявленной целевой функции |
| `webster_cycle_sec` | Цикл по формуле Уэбстера |
| `webster_lost_time_sec` | Потерянное время `L`, использованное в расчёте Уэбстера |
| `webster_flow_ratio` | Суммарный фазовый коэффициент `Y` в расчёте Уэбстера |
| `conflicts_by_phase` | Число конфликтов по фазам (заглушка до выбора и фиксации детализации) |
| `peak_max_queue` | Максимальная очередь на пиковом въезде в течение/после пика |
| `peak_recovery_time_sec` | Время восстановления после пика по заранее объявленному правилу |
| `adaptive_green_extensions` | Число продлений зелёного адаптивным контроллером |

Для реализованных показателей интервал наблюдения `[W, T]` применяется так: `generated`, `completed` и `conflicts` — приращения за интервал (значение на `T` минус значение на `W`); `delay_completed_sec` — средняя полная задержка автомобилей, завершивших поездку на интервале; `flow_completed_per_hour = completed · 3600 / (T − W)`; `mean_queue_after_warmup` и `max_queue_after_warmup` — по секундным отсчётам `t = W..T` (очередь — как в `Simulation.metrics`: ожидающие вне схемы и автомобили со скоростью ниже 1), `final_queue` — отсчёт `t = T`. `remaining = generated − completed` на интервале, то есть может быть отрицательным (завершились автомобили, появившиеся до `W`); число автомобилей в системе на момент `T` оно не показывает.

Поля `mean_queue_*`, `max_queue_*` и `mean_delay_*` заменяют суффикс `N/E/S/W` на конкретный въезд; в CSV должны присутствовать все четыре значения. Для показателей доверительных интервалов и парных разностей использовать поля сводки, а не вычислять их заново из уже агрегированных строк.

## Реестр SEED

Диапазоны включительны. Внутри одного сценария планам, сравниваемым попарно, назначаются соответствующие одинаковые SEED. Реестр является единственным источником назначения SEED; не выбирайте значения вне диапазонов без обновления контракта.

| Набор | Назначение | SEED | Правило |
| --- | --- | --- | --- |
| З1, общие | 20 пар сравнения двух планов на общих случайных потоках | `1–20` | Оба плана в каждой паре используют один и тот же SEED |
| З1, независимые — план A | 20 прогонов плана A | `1–20` | Сопоставляется с планом B по индексу пары, но потоки независимы |
| З1, независимые — план B | 20 прогонов плана B | `21–40` | Не пересекается с диапазоном плана A |
| З3 | Оценка точности, базовый план | `101–110` | 10 исходных прогонов; расширять диапазон по задаче T-34 |
| З4 | Поиск и настройка плана | `201–2xx` | Выделять новые SEED внутри диапазона по мере необходимости; фиксировать фактически использованные значения |
| З5/З6 | Фазовые схемы, пик и контроллер | `301–3xx` | Для сравниваемых вариантов использовать парные SEED; фиксировать фактически использованные значения |
| Holdout | Отложенная проверка | `901–930` | Запрещено использовать для настройки, выбора плана и любых предварительных сравнений до выполнения T-45 |

Диапазоны могут повторяться между независимыми экспериментами только в соответствии с их назначением выше. Расширение набора З3 производится по правилу T-34, а не выбором SEED из holdout. До T-45 holdout не загружается и не анализируется.

## Флаги CLI

Пакетный запуск поддерживает следующие флаги. Для параметров со значением `*` конкретные имена и типы задаются реализацией; все такие значения должны попадать в CSV и сохраняться в `options`.

| Флаг | Назначение |
| --- | --- |
| `--phase-scheme` | Схема фаз: двухфазная или выбранный вариант задания 5 |
| `--controller` | Политика управления: фиксированный план или адаптивный контроллер |
| `--peak-*` | Параметры пикового спроса: включение, въезд, время начала/окончания и множитель интенсивности |
| `--physics` | Вариант физических допущений; базовый режим использует исходную физику |

Флаги плана и серии (реализованы в `batch_runs.py`; значения по умолчанию — в `--help`):

| Флаг | Назначение |
| --- | --- |
| `--seconds`, `--warmup` | Горизонт `T` (60–3600 с) и прогрев `W` (`0 <= W < T`); по умолчанию 240 и 60 |
| `--seeds` | SEED через пробел или запятую, диапазоны включительно: `7 17`, `201-210`, `1,5,9-12`; повторы запрещены |
| `--cycle`, `--ns-green`, `--ew-green`, `--clearance` | План светофора; `cycle = ns_green + ew_green + 2·clearance`, недостающее выводится, противоречие — ошибка; зелёный не менее 6 с |
| `--demand-scale` | Множитель интенсивности спроса, 0,5–1,5 |
| `--grid` | Сетка З4: `CYCLE` 30–120 с шагом 10 × доля NS 0,30–0,70 с шагом 0,05 от `CYCLE − 2·clearance` (90 планов) |
| `--workers` | Число процессов `multiprocessing` (по умолчанию число ядер, `1` — без параллельности); результат от него не зависит |
| `--timeseries [PATH]` | Записать `timeseries_*.csv` |
| `--tag`, `--out`, `--summary`, `--demand-log`, `--no-demand-log` | Суффикс серии и пути файлов |

При отсутствии флагов сохраняется базовое поведение исходной модели. В README/help должны быть перечислены фактические подфлаги `--peak-*`, допустимые значения enum-параметров и значения по умолчанию. Все CLI-настройки, влияющие на прогон, должны быть отражены в его строке CSV.

## Python API

```text
from batch_runs import Plan, make_plan, evaluate, evaluate_grid, summarize, run_once

evaluate(plan, seeds, *, T=3600, W=300, demand_scale=1.0, options=None, workers=1) -> list[dict]
evaluate_grid(plans, seeds, *, T=3600, W=300, demand_scale=1.0, options=None, workers=None) -> list[dict]
```

`evaluate` возвращает по строке `run_once` на каждый SEED в порядке `seeds`; `evaluate_grid` — плоский список «план, затем SEED». `plan` — `Plan(cycle, ns_green, ew_green, clearance)`, словарь аргументов `make_plan` или `None` (базовый план `scenario.py`). `options` пока должен быть пустым: неподдерживаемые ключи вызывают `ValueError`, а не игнорируются. `summarize(rows)` строит строки `summary_*.csv`. Скрипты из `scripts/` запускаются из корня репозитория как `uv run python -m scripts.<имя>`.
