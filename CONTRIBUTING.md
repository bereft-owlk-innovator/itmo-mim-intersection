Как начать:
1. Клонировать репозиторий себе на машину
2. Установить [uv](https://docs.astral.sh/uv/getting-started/installation/)
3. Перейти в папку репозитория и выполнить `uv sync --locked`
   - Для запуска веб-приложения: `uv run python app.py`
   - Для пакетных запусков: `uv run python batch_runs.py`
   - Для проверки каркаса: `uv run python -m unittest test_starter.py`
4. Открыть свою задачу
5. Прочитать задачу и DoD ("Критерии готовности")
6. Перевести задачу в in-progress (чтобы другие люди, которые зависят на эту задачу, видели, что вы над ней работаете)
7. Создать ветку в репозитории с именем [номер задачи], (например itmo-mim-intersection/T-53)
8. Выполнить в этой ветке задачу
9. Запушить свой код в эту ветку
10. Создать pull request из этой ветки в main
11. Написать ревьюеру (указан в таске) и попросить поревьюить твой код

Предлагаю такой Code of Conduct
1. Если человек свою задачу не успел вовремя сделать, задача переключается на запасного тиммейта (зафиксированного в задаче). Если запасной тиммейт тоже не может, задача падает куратору (в данном случае это я). Таким образом, мы не сильно проседаем по дедлайнам если кто-то в силу различных обстоятельств не имеет возможности закрыть свои задачи. 
2. Перед тем, как задачу забрать - напишите и спросите у исполнителя, может быть, человек очень хочет ее закончить, просто еще не успел.
3. Я очень не хочу быть ежиком "Я тебя в книжечку запишу" , поэтому статусы будет собирать бот, его я добавлю в пятницу. В конце, ллмка просто суммаризует вклад каждого в зависимости от того, что будет написано в боте, это и пойдет в отчет и будет сдано преподавателю. Стеша, не жадничай и не делай весь проект одна, оставь другим возможность себя проявить!!
4. Данные из Linear и бота будут использоваться для компиляции таблицы вклада каждого участника. Если сделали таску - не забудьте закрыть ее в Linear, и (на всякий случай) отписаться в бота, а то потом все всё забудут и нужно будет долго и мучительно опрашивать каждого, кто чем занимался.
